# Fun where it adds value

Read this after the plain journey passes the beginner check and the identity is in place.

Polish makes a product feel finished. Fun makes it feel good to use. A design can be calm, clear and polished and still feel like a chore. This reference finds those moments and makes them lighter, without making them slower or less clear.

## What fun means here

Fun is the user enjoying a task they would otherwise put up with. It comes from:

- **doing instead of filling in:** touching, choosing or arranging something that looks like the real thing, instead of typing into a blank field;
- **seeing the effect at once:** each choice changes something visible before the user commits;
- **a reply from the product:** a character, object, sound or haptic that answers the user's action;
- **a human voice:** warm, specific wording from someone who knows the user's world;
- **an earned moment:** a short, rare reward when something meaningful is finished.

Fun is not decoration, confetti on every tap, points or pressure. It never replaces a clear label, and it never makes a frequent action slower.

## The chore test

Ask of every screen: "Does this feel like work?" A screen fails if a person would describe it as filling in, admin or homework. Common signs:

- a blank field for a number the user has to think up;
- a long list of identical rows or settings;
- a decision shown as abstract options, with no picture of what each one does;
- an empty state that only says nothing is here;
- a wait with only a spinner;
- an error or warning in a cold, official tone;
- a finish that ends with nothing, after something meaningful was done.

## Where fun earns its place

Look at these moments first. For each one, apply one move from the table, or record why none fits.

| Moment | Fun move |
| --- | --- |
| Entering numbers or personal details | Replace the blank field with direct manipulation of something meaningful: a dial, a stepper on a picture, a slider over a visual of the result, or a few named starting points the user can tune. Keep typing available. |
| Choosing between options | Make each option concrete. Show what it looks like or does, offer a friendly default, and show the result before the user confirms. |
| First use and empty states | Invite one easy first action with the product's character or objects. Offer a sample to play with. |
| Waiting | Show what is happening in the product's own world, with real steps and an honest end. |
| Finishing something meaningful | A short, earned moment the first time, quieter after. The character reacts or the object completes. Never for trivial actions. |
| Repeated chores, such as checking items off | Make the repeated action satisfying and fast: a crisp check, a haptic, a strike-through, a count going down. No extra steps. |
| Mistakes and warnings | Warm, blame-free wording and an obvious way out. A character may help, and never mocks. |
| Personal progress | Show the user's own progress as an object that grows or fills, in plain words, not scores or rankings. |
| Inviting or sharing | Make the message personal: the sender's name, and a preview of what the other person will see. |

## Techniques

- **Objects from the metaphor.** Let the product's metaphor give controls their form, such as a stepper of plates, a jar that fills or a ticket that tears.
- **Direct manipulation.** Drag, turn or tap the thing itself. Track the finger one to one, as [aliveness.md](aliveness.md) requires.
- **Live preview.** Every control changes something visible at once, before the user commits.
- **Character reactions.** Give the mascot a job in the moment, as the main skill describes, and use only its approved poses.
- **Voice.** One warm, specific line beats a paragraph. Be playful, but never less precise about what an action does.
- **Sound and haptics.** Optional and subtle, tied to an action, and off when the system says so.

## Guardrails

- **Frequency decides.** Use the frequency table in [aliveness.md](aliveness.md). Frequent actions stay fast, and their fun is a crisp response, not a show. Bigger moments are for rare events.
- **Clarity first.** Every playful control keeps a plain label and a familiar fallback, such as typing a number.
- **No pressure.** No streaks, scores, badges, leaderboards, guilt or loss framing unless the approved requirements include them. Fun serves the user's own goals, never the product's metrics.
- **Honest.** Playful visuals never distort numbers, results or what an action costs.
- **Accessible.** Works with a screen reader, larger text and reduced motion. A dial also accepts typed input and step buttons.
- **Wears well.** Picture the 50th use. If the moment would annoy by then, make it quieter or rarer.
- **Fits the audience.** Humour and references suit the user's culture and the weight of the task. Health, money and safety moments stay calm and exact.
- **Scope.** Fun changes how a required task feels. It does not add features. Propose a new feature separately, as added scope.

## Review

In the adversarial review, run this fun audit after the identity checks:

1. For each screen, say whether it passes the chore test.
2. For each failing moment in the table above, name one fun move that adds value, or say why none fits.
3. Reject any fun move that breaks a guardrail.
4. Run the 50th-use test on the screens people see most often.
